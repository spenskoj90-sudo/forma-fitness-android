# FORMA · пилот ИИ-разработки

Пилот запускает синтетическую задачу `clamp-v1` в Linux. Основной профиль вызывает один инструмент редактирования через локальный llama.cpp. Запасной профиль использует другую модель и ограниченный JSON-ответ. OpenCode 1.19.5 выполнил отдельный синтетический прогон. В ограниченной оболочке этого пилота OpenCode давал нестабильный результат, поэтому workflow вызывает модель через узкий проверяемый исполнитель. Обе модели работают на CPU, без аккаунта и API-ключа. Проверяющий процесс допускает только выражение в ограниченной грамматике и независимо проверяет 257 входов. У синтетического результата нет доступа к продуктовым веткам и подписи.

## Infinix и Poco

1. После проверки и слияния PR откройте в браузере [Actions](https://github.com/spenskoj90-sudo/forma-fitness-android/actions). Выберите **AI development pilot (synthetic)**, затем **Run workflow**. При скрытой кнопке включите версию сайта для ПК.
2. Выберите ветку `main`, задачу `clamp-v1` и профиль `qwen3-1.7b`. Скопируйте полный SHA последнего коммита `main` в `expected_sha`. Запуск со сдвинувшимся SHA завершится ошибкой.
3. В карточке прогона откройте логи и скачайте **forma-ai-pilot-…** из **Artifacts**. В архиве находятся `checkpoint.json` и проверенный `candidate.patch` при PASS. Диагностические APK по-прежнему доступны из отдельного существующего Android workflow.
4. Для остановки используйте **Cancel workflow** и дождитесь завершения. Если сохранён артефакт, запустите снова с тем же SHA и номером предыдущего прогона в `resume_run`. После сохранённого предложения повторный запуск заново проверит патч без обращения к модели. При отмене до публикации артефакта запускайте задачу с начала. Артефакт хранится семь дней.
5. При ошибке модели дождитесь завершения прогона и выберите `qwen2.5-coder-3b` в новом запуске. Если для того же SHA уже сохранено проверяемое предложение и указан `resume_run`, приоритет имеет сохранённое предложение. Для независимого сравнения моделей оставьте поле возобновления пустым.

## Linux

```bash
python3 -m unittest discover -s scripts/ai-pilot -v
bash scripts/ai-pilot/run-local.sh "$(git rev-parse HEAD)" /tmp/forma-ai-pilot
```

Для восстановления используйте тот же каталог и SHA. Для резерва передайте `qwen2.5-coder-3b` третьим аргументом. Для параллельных локальных прогонов используйте отдельные каталоги и разные свободные порты через `PILOT_PORT`. Передавайте SHA текущего checkout. Загрузка бинарников и весов проверяется по SHA-256. Скачивание основной модели требует около 1,84 ГБ трафика, запасной около 2,10 ГБ.

## Работа с GitHub

У workflow есть только `contents: read` и `actions: read`. В шаге восстановления временный токен применяется к GitHub. Исполнитель обращается только к локальной модели и отправляет ей синтетический пример. Публикация настоящего изменения требует отдельного проверенного исполнителя ветки, проверки exact HEAD/base, обычного draft PR и чтения статусов CI. Действующий журнал PROJECTS находится в [#532](https://github.com/spenskoj90-sudo/alpha-0/issues/532). Прогон пилота подтверждает работу одной синтетической задачи. Для продуктового маршрута отдельно требуется проверенная публикация PR и доказательства CI на итоговом SHA.

## Очередь FORMA

**FORMA AI work queue** запускает один из заранее проверенных пакетов с телефона через Actions. Для первого прогона выберите `backup-replay` и укажите точный SHA `main`. Пакет повторяет дефект PR #15 на реальных исходниках `domain` во временном каталоге и затем обрабатывает две синтетические задачи, вторая из которых зависит от первой. Пакет `smoke` проверяет только синтетическую часть. Если исправление PR #15 уже вошло в выбранный коммит, повтор требует исторического исходного кода и завершается с сообщением о неподходящей базе.

Один исполнитель предлагает ограниченное изменение, тесты и компилятор дают обратную связь, вторая локальная модель проверяет diff. Очередь допускает до двух попыток на модель. Ошибка связи переводит предложение на запасную модель. При исчерпании попыток зависимые шаги ждут, независимые выполняются. Для допуска патча обязательны и проверки, и независимое ревью. Результаты и следующие действия видны в сводке запуска. Готовые патчи и `queue.json` находятся в артефакте прогона.

Чтобы возобновить оборванный прогон, дождитесь его завершения и передайте его номер в `resume_run`, сохранив пакет и SHA. Восстановление возможно, если GitHub успел сохранить артефакт. Локальный запуск сохраняет предложенное изменение и итог каждой попытки в выходном каталоге. Если процесс прервался во время проверки или ревью, сохранённое предложение проходит проверки повторно. При полном исчерпании попыток изучите обратную связь и начните новый запуск с проверенным изменением пакета или модели. Workflow поддерживает только ручной запуск с `main` после интеграции.

```bash
bash scripts/ai-pilot/run-queue.sh "$(git rev-parse HEAD)" /tmp/forma-ai-queue backup-replay
```

Пилот принимает только проверенные пакеты из исходников репозитория. У workflow права чтения. Он сохраняет патчи для ревью, а публикация PR остаётся отдельным шагом с проверкой точного SHA и прав. Итоговый журнал находится в [PROJECTS #532](https://github.com/spenskoj90-sudo/alpha-0/issues/532).
